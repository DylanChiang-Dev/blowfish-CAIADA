# 官網倉庫架構重整計劃 v0.0.2

日期：2026-05-22

## 決策摘要

- 採用單一官網倉庫自給自足架構。
- `blowfish-CAIADA` 倉庫根目錄直接作為 Hugo 網站根。
- `themes/blowfish/` 內完整保存 Blowfish 主題源碼，作為普通 Git tracked directory。
- 不使用 Git submodule，不依賴官方主題倉庫在部署時可用。
- v0.0.1 的官方 submodule 方案保留為歷史記錄，但不再執行。

## 目標結構

```text
blowfish-CAIADA/
├── content/                       # 官網內容
├── assets/
│   └── img/                       # 協會自有圖片
├── config/
│   └── _default/                  # Hugo 與多語言配置
├── layouts/                       # 官網自定義模板覆寫
├── themes/
│   └── blowfish/                  # 已 vendor 的 Blowfish 主題源碼
├── plans/                         # 技術計劃
├── AGENTS.md
├── RULES.md
├── MEMORY.md
└── README.md
```

## 本地開發與建置

```bash
hugo server
hugo --minify --gc
```

## Cloudflare Pages 配置

| 設定項 | 值 |
|---|---|
| 建置命令 | `hugo --minify --gc` |
| 輸出目錄 | `public` |
| 根目錄 | `/` |
| `HUGO_VERSION` | `0.161.1` |

Cloudflare Pages 後台仍需手動將根目錄從舊的 `exampleSite` 改為 `/`。

## 實施步驟

1. 移除 `.gitmodules`。
2. 移除 `themes/blowfish` 的 gitlink/submodule 元資料。
3. 將 `themes/blowfish/` 重新作為普通檔案納入 Git。
4. 保留官網根目錄結構：`content/`、`config/_default/`、`assets/img/`、必要的 `layouts/partials/`。
5. 刪除舊 `exampleSite/` 和舊主題開發倉庫根目錄中與官網無關的檔案。
6. 更新 `README.md`、`AGENTS.md`、`MEMORY.md` 為 vendor 主題事實。
7. 執行 `hugo --minify --gc` 驗證建置。
8. 執行 `hugo server` 驗證首頁、關於、章程、新聞和山東參訪文章。

## 後續主題更新策略

- 不自動追蹤上游。
- 預設一年左右按需更新一次。
- 更新時另開任務，手動拉取新版 Blowfish，比較差異後覆蓋 `themes/blowfish/`，再完整跑 Hugo 建置與頁面驗證。
